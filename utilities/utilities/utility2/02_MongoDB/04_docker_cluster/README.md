# MongoDB — Docker Compose HA cluster (SHARDED: mongos + config-RS + 2 shards)

A real **sharded cluster** — horizontal sharding **plus** per-shard replication **plus** read/write split,
the same topology a production fleet uses, on the official `mongo:7.0` image. Tested on Ubuntu 26.04.

| Component | Members | Role |
|---|---|---|
| **config-RS** `csrs` | `cfg1` | cluster metadata (configsvr replica set) |
| **shard 1** `rs-shard1` | `s1a` (primary) + `s1b` (secondary) | one chunk-range of the sharded data |
| **shard 2** `rs-shard2` | `s2a` (primary) + `s2b` (secondary) | the other chunk-range |
| **mongos** | `mongos` :27017 | the query router — the single client entry point |

```text
                     ┌──────────────────────────────┐
        client  ───► │  mongos :27017  (query router)│ ──► routes by shard key (hashed _id)
                     └───────────────┬───────────────┘
            ┌────────────────────────┼────────────────────────┐
            ▼                        ▼                         ▼
   ┌────────────────┐      ┌──────────────────┐      ┌──────────────────┐
   │ config-RS csrs │      │ shard rs-shard1  │      │ shard rs-shard2  │
   │ cfg1 (metadata)│      │ s1a(P) ──► s1b(S)│      │ s2a(P) ──► s2b(S)│
   └────────────────┘      └──────────────────┘      └──────────────────┘
```

Writes route to the owning shard's **primary**; reads can target **secondaries** via `readPreference`.
**keyFile** internal auth on every component (generated by `setup.sh`); the cluster **root** user lives on
the config servers. Per-component data are **host bind mounts** (survive `down -v`).

Install / test / uninstall each come in **two interchangeable ways**: **A. Scripted** — `setup.sh`
(generates the keyFile + root password, initiates all replica sets, adds the shards, shards a sample
collection, runs the acceptance, prints a credentials summary); and **B. Manual** — raw
`docker compose` + `mongosh` commands that reproduce that init by hand.

## Files

- `docker-compose.yml` — `cfg1` + `s1a/s1b` + `s2a/s2b` + `mongos` (all share the keyFile read-only).
- `setup.sh` — up / accept / down / purge / status / logs.
- `.env.example` — copy to `.env`.

## How it works (and why the data survives `down -v`)

- Each component stores its data on a **host bind mount** at `${DATA_ROOT}/mongodb_sharded/{cfg1,s1a,s1b,s2a,s2b}`
  → the container's `/data/db`, plus a shared **keyFile** at `${KEYFILE_HOST_PATH}` (default
  `${DATA_ROOT}/mongodb_sharded/keyfile`). There is **no named volume**, so `docker compose down -v` keeps
  all the data + the keyFile, and the cluster comes back on `up`.
- **Replication/sharding is NOT automatic on `up`** — unlike a single replica set, a sharded cluster needs
  an explicit init. `setup.sh up` runs it: start the config + shard mongods, **`rs.initiate`** the config-RS
  and both shard replica sets (member 0 gets `priority:2` so it is deterministically the primary), create a
  shard-local `root` user on each shard primary, start **mongos**, create the cluster `root` user via the
  mongos **localhost exception**, **`sh.addShard`** both shards, then **`sh.enableSharding`** +
  **`sh.shardCollection`** a sample `dokandar.items` (hashed `_id`). The manual path below reproduces this
  exactly.

## Prerequisites

Docker Engine + Compose plugin (see `../03_docker_single/README.md` for the install). You also need
`openssl` (for the keyFile) — it ships with Ubuntu. You do **not** need a host `mongosh`: every command
below runs `mongosh` inside a container via `docker exec`.

## Configure

```bash
cp .env.example .env        # set MONGOS_PORT if 27017 is taken; image tag / DATA_ROOT optional
```

`.env` is gitignored; only `.env.example` is committed. Key vars: `MONGO_VERSION` (`7.0`),
`MONGO_ROOT_USER` (default `dokandar`), `MONGO_ROOT_PASSWORD`, `MONGOS_PORT` (host port → mongos `27017`),
`SHARD_DB` (the db whose `items` collection is sharded, default `dokandar`), `KEYFILE_HOST_PATH`,
`DATA_ROOT`. **Leave `MONGO_ROOT_PASSWORD` empty to auto-generate a complex (24-char) password** —
`setup.sh up` fills it before bringing the cluster up and saves it back to `.env`. Unlike the single-node
compose, the cluster containers come up with **keyFile** internal auth and **no** `MONGO_INITDB_*` — the
root user is created by hand via the mongos localhost exception, so the image does **not** require a
password to start. **Set `MONGO_ROOT_PASSWORD` non-empty in `.env` anyway**, because the manual path uses
that literal in every `createUser`/`addShard` command **and** `test.sh 04_docker_cluster` reads it from
`.env` to build the mongos connection URI. If `27017` is taken on this host (a native or single-node
MongoDB already runs), change `MONGOS_PORT` (e.g. `27037`).

## Install / up

### A. Scripted install (recommended)

```bash
bash setup.sh up                 # generates keyFile + root password, builds the whole sharded cluster, runs acceptance
bash setup.sh up --gen-password  # rotate the root password
bash setup.sh up --password 'MyOwnSecret'   # or set it explicitly
```

`up` (6 steps): resolve password + keyFile + data dirs → start the config + shard mongods → **initiate**
the config-RS + both shard replica sets (+ shard-local admin users) → start **mongos** + create the
**root** user (localhost exception) → **add both shards** + shard `dokandar.items` (hashed `_id`) →
**acceptance**. Ends with a **credentials summary** (mongos URI + password) for copy-paste. The password
is shown once and saved to `.env`.

### B. Manual install (raw docker compose + mongosh)

Run these by hand — they are exactly what `setup.sh up` does. Pick your own root password where shown.
**The shard/config replica sets and shards are NOT auto-initiated by the entrypoint — you run the
`rs.initiate` / `addShard` / `shardCollection` steps below.**

```bash
# 1. env file + root password (used in the createUser commands below AND by test.sh's URI) + data dirs + keyFile
cp .env.example .env
sed -i "s/^MONGO_ROOT_PASSWORD=.*/MONGO_ROOT_PASSWORD=ChangeMe_StrongPassword/" .env
sudo mkdir -p /data/mongodb_sharded/{cfg1,s1a,s1b,s2a,s2b}
openssl rand -base64 756 | sudo tee /data/mongodb_sharded/keyfile >/dev/null
sudo chmod 400 /data/mongodb_sharded/keyfile
sudo chown 999:999 /data/mongodb_sharded/keyfile /data/mongodb_sharded/{cfg1,s1a,s1b,s2a,s2b}

# 2. start the config server + shard mongods (NOT mongos yet)
docker compose up -d cfg1 s1a s1b s2a s2b
# wait until each mongod answers before initiating (matches setup.sh's ping_up loop):
for c in cfg1 s1a s2a; do
  until docker exec dokandar_mongo_$c mongosh --quiet --port 27017 --eval 'db.runCommand({ping:1}).ok' 2>/dev/null | grep -q 1; do sleep 2; done
done

# 3. initiate the config replica set + both shard replica sets (member 0 priority:2 → deterministic primary)
docker exec dokandar_mongo_cfg1 mongosh --quiet --port 27017 --eval \
  "rs.initiate({_id:'csrs',configsvr:true,members:[{_id:0,host:'cfg1:27017'}]})"
docker exec dokandar_mongo_s1a mongosh --quiet --port 27017 --eval \
  "rs.initiate({_id:'rs-shard1',members:[{_id:0,host:'s1a:27017',priority:2},{_id:1,host:'s1b:27017'}]})"
docker exec dokandar_mongo_s2a mongosh --quiet --port 27017 --eval \
  "rs.initiate({_id:'rs-shard2',members:[{_id:0,host:'s2a:27017',priority:2},{_id:1,host:'s2b:27017'}]})"
# wait for each to be elected PRIMARY before creating users (matches setup.sh's wait_primary loop):
for c in cfg1 s1a s2a; do
  until [ "$(docker exec dokandar_mongo_$c mongosh --quiet --port 27017 --eval 'db.hello().isWritablePrimary' 2>/dev/null)" = true ]; do sleep 2; done
done

# 3b. a shard-local root user on each shard primary (so the acceptance can query shards DIRECTLY)
for c in s1a s2a; do docker exec dokandar_mongo_$c mongosh --quiet --port 27017 --eval \
  "db.getSiblingDB('admin').createUser({user:'dokandar',pwd:'ChangeMe_StrongPassword',roles:[{role:'root',db:'admin'}]})"; done

# 4. start mongos + create the cluster root user via the localhost exception
docker compose up -d mongos
# wait until mongos answers before creating the user (matches setup.sh's ping_up loop):
until docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 --eval 'db.runCommand({ping:1}).ok' 2>/dev/null | grep -q 1; do sleep 2; done
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 --eval \
  "db.getSiblingDB('admin').createUser({user:'dokandar',pwd:'ChangeMe_StrongPassword',roles:[{role:'root',db:'admin'}]})"

# 5. add both shards + shard a sample collection (authenticated, via mongos)
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 \
  -u dokandar -p 'ChangeMe_StrongPassword' --authenticationDatabase admin --eval \
  "sh.addShard('rs-shard1/s1a:27017,s1b:27017'); sh.addShard('rs-shard2/s2a:27017,s2b:27017')"
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 \
  -u dokandar -p 'ChangeMe_StrongPassword' --authenticationDatabase admin --eval \
  "sh.enableSharding('dokandar'); db.getSiblingDB('dokandar').createCollection('items'); sh.shardCollection('dokandar.items',{_id:'hashed'})"

# 6. verify both shards registered (should print 2)
docker compose ps
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 \
  -u dokandar -p 'ChangeMe_StrongPassword' --authenticationDatabase admin --eval \
  "db.getSiblingDB('config').shards.countDocuments({})"     # -> 2
```

## Verify the cluster (HA acceptance)

### A. Scripted acceptance

```bash
bash setup.sh accept
```

Runs the 4 acceptance criteria: **(1)** 2 shards registered; **(2)** 200 docs written via mongos
**distribute across both shards** (each shard primary holds a slice, sum = 200); **(3)** a shard's
**secondary** (`s1b`) has replicated the primary's docs; **(4)** a **secondary-preferred read via mongos**
returns the UTF-8 doc (`চাল-42`). Cleans up the 200 docs after itself.

### B. Manual acceptance (write distributes → secondary replicates → secondary-preferred read)

```bash
# (2) write 200 docs via mongos → they DISTRIBUTE across both shards (hashed _id)
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 \
  -u dokandar -p 'ChangeMe_StrongPassword' --authenticationDatabase admin --eval \
  "var b=db.getSiblingDB('dokandar').items.initializeUnorderedBulkOp(); for(var i=0;i<200;i++){b.insert({_id:i,v:'চাল-'+i})}; b.execute()"

# per-shard physical counts on each shard PRIMARY — both must be > 0 and sum to 200:
docker exec dokandar_mongo_s1a mongosh --quiet --port 27017 -u dokandar -p 'ChangeMe_StrongPassword' \
  --authenticationDatabase admin --eval "db.getSiblingDB('dokandar').items.countDocuments({})"   # shard1 slice
docker exec dokandar_mongo_s2a mongosh --quiet --port 27017 -u dokandar -p 'ChangeMe_StrongPassword' \
  --authenticationDatabase admin --eval "db.getSiblingDB('dokandar').items.countDocuments({})"   # shard2 slice

# (3) per-shard replication: shard1 SECONDARY (s1b) has the primary's docs
docker exec dokandar_mongo_s1b mongosh --quiet --port 27017 -u dokandar -p 'ChangeMe_StrongPassword' \
  --authenticationDatabase admin --eval \
  "db.getMongo().setReadPref('secondaryPreferred'); db.getSiblingDB('dokandar').items.countDocuments({})"

# (4) read/write split: secondary-preferred read via mongos returns the UTF-8 doc
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 -u dokandar -p 'ChangeMe_StrongPassword' \
  --authenticationDatabase admin --eval \
  "db.getSiblingDB('dokandar').getMongo().setReadPref('secondaryPreferred'); db.getSiblingDB('dokandar').items.findOne({_id:42}).v"   # -> চাল-42

# clean up the 200 acceptance docs
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 -u dokandar -p 'ChangeMe_StrongPassword' \
  --authenticationDatabase admin --eval "db.getSiblingDB('dokandar').items.deleteMany({})"
```

## Test (the shared contract test, against mongos)

### A. Scripted test

```bash
# from utility/02_MongoDB/  (reads this variant's .env → connects to mongos)
bash test.sh 04_docker_cluster
# cross-host — paste the mongos URI setup.sh printed:
bash test.sh "mongodb://dokandar:<pw>@<host>:27017/?authSource=admin"
```

The test connects to **mongos** and runs the full CRUD / aggregation / UNIQUE-index / UTF-8 contract (routed
to the right shard transparently), proving zero residue.

### B. Manual test (raw write → read → clean-up, via mongos)

```bash
docker exec dokandar_mongo_mongos mongosh --quiet --port 27017 \
  -u dokandar -p 'ChangeMe_StrongPassword' --authenticationDatabase admin <<'JS'
db = db.getSiblingDB('dokandar_smoke');
db.probe.insertOne({ name_bn: 'চাল', name_en: 'rice', at: new Date() });
printjson(db.probe.findOne({ name_en: 'rice' }));            // -> { name_bn: 'চাল', ... }
db.dropDatabase();                                           // clean up — zero residue
JS
```

## Connection model

- **All client traffic → mongos** (`127.0.0.1:${MONGOS_PORT}`, default `27017`) — the single entry point.
  It routes each write to the owning shard's primary by the hashed `_id` shard key.
- **Reads** can target secondaries with a `readPreference` of `secondary`/`secondaryPreferred` on the
  connection or per-query.

## Uninstall

### A. Scripted uninstall

```bash
bash setup.sh down          # stop + remove all 6 containers — data + keyFile PRESERVED
bash setup.sh purge         # docker compose down -v + rm -rf /data/mongodb_sharded (data + keyFile gone)
```

### B. Manual uninstall (raw docker compose)

```bash
# stop + remove the containers — bind-mounted data + keyFile are PRESERVED either way
docker compose down               # data kept
docker compose down -v            # also fine — bind mounts survive -v

# full wipe — ALSO delete the per-component data + keyFile (irreversible)
docker compose down -v
sudo rm -rf /data/mongodb_sharded
```
