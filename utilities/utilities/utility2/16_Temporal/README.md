# Temporal — utility dependency

Temporal 1.31 is DOKANDAR's **durable workflow engine** — it orchestrates the checkout **order saga**
(`13-order`), with replayable, compensating workflows on payment/stock failure. This folder holds the
install variants plus a **shared test script** for all of them.

## Layout

```text
16_Temporal/
├── README.md            ← this file
├── test.sh              ← shared contract/smoke test (namespace CRUD, via the temporal CLI) — all variants
├── 01_native_single/    ← native (no Docker), CLI binary + systemd, `server start-dev` (SQLite)         [TESTED]
├── 03_docker_single/    ← Docker Compose, dev server (admin-tools start-dev), SQLite bind-mounted        [TESTED]
└── 04_docker_cluster/   ← Docker Compose HA: PostgreSQL + 3 temporal-server nodes + Web UI               [TESTED]
```

(`02_native_cluster` is intentionally skipped — the Dockerised PG-backed 3-node cluster covers HA.)

> **Architecture.** Single-node (`01`/`03`) runs the **dev server** (`temporal server start-dev`) — the
> full frontend/history/matching/worker in one process, persisted to **SQLite**, with the built-in Web UI.
> HA (`04`) runs the **production** path: a **PostgreSQL** durable store + **3 temporal-server nodes** (all
> 4 roles each) sharing it — Temporal's services are stateless, so HA comes from the shared DB +
> `cluster_membership` rings, surviving one node loss.

> **Auth & UI.** The dev server has **no auth**; the cluster's only secret is the **PostgreSQL password**
> (auto-generated by `setup.sh`, saved to `.env` chmod 600). The **Web UI** is the dev server's built-in UI
> (`:8233`) or the companion **temporalio/ui** (cluster). Tests run over an SG-fenced VPC.

## The shared test script — `test.sh`

Uses the **`temporal` CLI** against the frontend gRPC. It confirms connectivity, creates a throwaway
**namespace** with a bilingual-UTF-8 description, reads it back (describe + list), then **deletes** the
namespace and **proves zero residue**. It is **worker-free** — it exercises the frontend + persistence via
namespace CRUD, not a running workflow.

### How to run it

```bash
bash test.sh 03_docker_single     # reads host/port from its .env
# or against ANY Temporal frontend (e.g. cross-host):
TEMPORAL_HOST=<host> TEMPORAL_GRPC_PORT=7233 bash test.sh
```

Client auto-selects: **host** `temporal` if on PATH, else `temporal` inside a **`temporalio/admin-tools`**
Docker container (`--network host`).

### Reading the result

`RESULT: PASS — namespace created/described/deleted, zero residue.` and exit `0` means the frontend +
persistence work and the namespace store is clean. Any failure prints the failing checks.
